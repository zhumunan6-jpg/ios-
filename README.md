# 中文多音频播放器 PWA MVP

这是一个完全免费的静态 PWA 音频播放器。前端固定保留“工作音乐”和“娱乐音乐”两个一级分类，每个分类可以混合放置单首音频和歌单。点击歌单后进入歌单内部的音频列表，支持分类或歌单内的播放、顺序播放和单曲循环。

音频通过播放器中的“本机上传”从 iPhone“文件”App 导入，并保存在当前 PWA 的 IndexedDB 私有存储中。音频不会上传到服务器，也不会写入 GitHub 仓库。

## 本地运行

```bash
npm start
```

然后打开 `http://localhost:4173`。

## iPhone / iOS 使用教程

### 方式一：使用 GitHub Pages（推荐）

1. 在 iPhone 上使用 Safari 打开上面的 GitHub Pages 地址。
2. 点击 Safari 的“分享”按钮，选择“添加到主屏幕”，然后从主屏幕打开“中文音频播放器”。
3. 点击“本机上传”。在“文件”App 中进入“浏览”，找到音频文件并选择。当前版本允许选择任意文件，应用会在确认导入时判断是否为支持的音频格式。
4. 选择一级分类，再选择直接放入分类、新建歌单或加入已有歌单，点击“确认导入”。
5. 返回列表，点击音频名称或“播放”按钮开始播放。

音频只保存在当前 iPhone 的浏览器/PWA 本地存储中，不会上传到 GitHub 或其他服务器。建议之后一直从同一个主屏幕图标进入，以免混淆不同入口中的本地数据。

### 方式二：使用电脑本地服务测试

确保电脑和 iPhone 连接到同一个 Wi-Fi：

1. 在电脑项目目录运行 `npm start`。
2. 在 Windows PowerShell 中运行 `ipconfig`，找到电脑的局域网 IPv4 地址，例如 `192.168.1.20`。
3. 在 iPhone Safari 打开 `http://192.168.1.20:4173`，将 IP 替换为电脑实际地址。
4. 进行导入和播放测试。

本地 HTTP 地址适合测试页面、导入和播放；Service Worker 离线缓存和主屏幕 PWA 建议使用 HTTPS 的 GitHub Pages 地址验证。如果手机无法打开本地地址，请检查电脑防火墙是否允许 Node.js 接受局域网连接。

### iOS 支持的音频格式

当前应用导入校验支持：

- M4A（建议使用 AAC-LC 编码）
- AAC
- MP3
- WAV（建议使用 PCM 编码）

M4A 是容器格式，具体能否播放还取决于内部编码。FLAC、OGG、OPUS、WMA、APE 等格式当前不会导入。

### 大文件和本地存储

音频会完整保存到 iPhone 的 IndexedDB 中。单个大文件可能受到 iOS 可用存储空间、浏览器配额或内存限制影响。建议先用较小文件测试；将大文件拆成多个小文件可以降低单次导入压力，但不能减少总存储空间需求。必要时应降低码率或压缩音频。

### 常见问题

- **文件在“文件”App 中仍然是灰色**：关闭旧的主屏幕 PWA，用 Safari 重新打开最新地址并刷新后再试。当前版本的选择器使用 `accept="*/*"`，不应再按 `audio/*` 提前过滤。
- **可以选择，但确认导入后提示格式不支持**：确认文件扩展名为 `.m4a`、`.aac`、`.mp3` 或 `.wav`，并确认文件内容确实是音频。
- **已经导入，但播放失败**：通常是音频内部编码不被 iOS Safari 支持，建议转换为 AAC-LC M4A、MP3 或 PCM WAV。
- **导入大文件失败**：先删除不需要的本地音频、尝试拆分文件或降低码率；清除网站数据会同时删除已导入的本地音频。

## 从本机添加音频

点击“本机上传”，从 iPhone“文件”App 选择一个或多个文件，然后选择一级分类和目标位置：直接进入分类、新建歌单或加入已有歌单。选择器允许选择任意文件，应用会在确认导入时校验音频格式；一次选择的多个文件会进入同一个目标。

音频标题默认使用原始文件名。重复文件会自动跳过，不支持的格式不会转码。当前建议优先使用 iOS Safari 能播放的 AAC 编码 M4A、MP3 或 WAV 文件。

列表中的“移动”可以将音频移动到一级分类或已有歌单；“删除”会从本机音频库永久删除文件。删除歌单只会解除歌单关系，歌单内音频会保留在一级分类中。

音频仅保存在本机。清除网站数据、系统存储压力或浏览器数据清理都可能导致本地音频丢失。
